

## Git Workflow

Whenever a member wants to add code, we first create a branch for the feature we want to implement, write in our branch (and push), and then create a pull request where another member of the team needs to approve for it to be merged into main. 

## Team Norms

### Team Values
- We will work together by assigning tasks together and ensuring all of us complete the tasks correctly in a timely manner.
- In the event any of us need help, we keep open communication through Discord and other channels and are quick to respond to eachother's requests
- We resolve conflicts by presenting issues to the group and possibly admins if needed to see what changes may need to be done

### Sprint Cadence
- Our sprint duration is 2 weeks

### Daily Standups
- Normally Wednesdays, Thursdays, and Fridays but these are tentative as the group is very flexible
- We are all present synchronously
- Members will not cover for other members who do not participate.
- Members who make no progress on a task for two standups or more in a row will be reported to management

### Coding Standards
- We all use VS Code and Prettier extension for linting
- All code must be peer-reviewed and pass tests before merging into main
- Keep the tree clean and delete branches once they have been merged
- Make sure to remove any commented out/dead code 
- Make sure your commit messages are clear
- For code that is not straightforward, use comments

## Contribution Instructions

### What to Contribute
Contributions may include bug fixes, new features, documentation, and usability improvements.

### Before You Start
- Check existing issues and pull requests to avoid duplicating work.
- Create or comment on an issue describing your proposed contribution.
- Discuss significant changes with the team before implementation.

### Contribution Requirements
- Follow the project's existing code style and organization.
- Update relevant documentation when changing functionality.
- Never commit passwords, API keys, or other sensitive information.
- Keep changes focused on the agreed issue or task.

### Submitting Your Contribution
- Follow the Git workflow described in this document.
- Give your pull request a clear title and describe what changed and why.
- Link the related issue and explain how changes were checked.
- Request a review from another team member. 
- Address review feedback and obtain another team member's approval before merging into main.
